## 1. Описание интеграции

### Какие источники данных выбраны

Выполнена **комбинированная интеграция** (покрыты все три типа из методички):

| Тип | Источник | Роль в продукте |
|---|---|---|
| Файлы (CSV) | `numbeo_cities.csv` — индексы Numbeo для 57 городов | Сырой источник статистики стоимости/качества жизни |
| База данных (SQLite) | `geo_quiz.db` | Единое хранилище: города, статистика, игроки, история партий |
| Данные пользователей | Telegram `user_id` (`update.effective_user`) | Персонализация: рейтинг игроков и личная статистика |

### Почему именно эти источники

1. **Обратная связь по лабораторной №1:** преподаватель отметил, что JSON-файл ограничен по объёму и не поддерживает запросы. SQLite снимает оба ограничения: данные хранятся в одном файле, но доступны через SQL с индексами и безопасной параллельной записью.
2. **Numbeo** — крупнейшая краудсорсинговая база стоимости жизни; её индексы (Нью-Йорк = 100) дали product-апгрейд: 12 новых типов вопросов и образовательные «фан-факты».
3. **CSV как промежуточный слой** реализует классический **ETL-пайплайн** (Extract → Transform → Load): данные извлекаются из файлов, связываются по имени города и загружаются в SQLite скриптом `import_data.py`. В продакшен-версии CSV-слой заменяется на периодические запросы к Numbeo API.

### Структура данных

**Схема базы `geo_quiz.db`:**

```sql
cities (id PK, name UNIQUE, population, latitude, altitude, avg_temp,
        area, year_founded, metro_stations, annual_tourists)
city_stats (city_id PK/FK → cities.id,
            cost_of_living_index, rent_index, safety_index,
            pollution_index, quality_of_life_index, climate_index)
players (user_id PK, username, first_name, games_played, best_streak,
         current_streak, total_correct, total_answers,
         registered_at, last_played_at)
game_log (id PK, user_id, city_name, param_key, is_correct, created_at)
used_questions (question_id PK)
```

**ETL-конвейер:**

```
cities.json ────────┐
                    ├──▶ import_data.py ──▶ geo_quiz.db ──▶ bot.py
numbeo_cities.csv ──┘        (ETL)          (SQLite)       (чтение через SQL)
```

**Особенность реальных данных:** 4 города из 61 (Омск, Воронеж, Пермь, Пхеньян) не имеют индексов Numbeo. Это обработано штатно: вопросы по индексам строятся только через `JOIN cities ⋈ city_stats`, поэтому города без статистики автоматически исключаются из новых категорий вопросов, а бот не падает.

## 3. Реализация

### Как работает интеграция

1. **Загрузка данных (однократно):** `import_data.py` создаёт таблицы и наполняет их из `cities.json` и `numbeo_cities.csv`, связывая записи по очищенному имени города.
2. **Чтение:** бот не хранит данные в памяти — каждый вопрос собирается SQL-запросом (`SELECT` по всем городам или `JOIN` с индексами).
3. **Запись:** каждый ответ фиксируется транзакцией: обновляется серия/рекорд игрока и пишется строка в `game_log`.
4. **Генерация вопроса:** выбирается параметр → якорный город → диапазон отклонения по уровню сложности → 3 «города-обманки» с близкими значениями → проверка уникальности значений → формулировка «больше/меньше» → определение правильного ответа.
5. **Фан-факт:** после верного ответа бот считает место города в рейтинге по случайному индексу Numbeo (`ORDER BY` по пулу городов с индексами).

### Ключевые фрагменты кода

**Связывание городов с индексами (SQL JOIN):**
```python
def load_cities_with_stats():
    conn = get_db()
    rows = [dict(r) for r in conn.execute("""
        SELECT c.*, s.cost_of_living_index, s.rent_index, s.safety_index,
               s.pollution_index, s.quality_of_life_index, s.climate_index
        FROM cities c JOIN city_stats s ON s.city_id = c.id
    """)]
    conn.close()
    return rows
```

**Регистрация игрока по user_id (идемпотентно):**
```python
conn.execute(
    "INSERT OR IGNORE INTO players (user_id, username, first_name) VALUES (?,?,?)",
    (user.id, user.username, user.first_name))
```

**Рейтинг игроков (SQL-агрегация и сортировка):**
```python
rows = conn.execute("""SELECT first_name, username, best_streak, games_played
                       FROM players ORDER BY best_streak DESC, games_played DESC
                       LIMIT 10""").fetchall()
```

**Прогрессивная сложность (диапазоны отклонения):**
```python
PERCENT_DEVIATION = {1: 0.5, 2: 0.3, 3: 0.15, 4: 0.07}   # население, площадь, туристы
ABS_DEVIATION = {"cost_of_living_index": {1: 30, 2: 18, 3: 9, 4: 4}, ...}
```

## 5. Трудности и решения

| Трудность | Решение |
|---|---|
| JSON не масштабируется и не поддерживает запросы (фидбек по лаб. №1) | Переход на SQLite: SQL-запросы, индексы, безопасная параллельная запись |
| Имена городов в базе содержат эмодзи-флаги и не совпадают с CSV | Функция `clean_name()`: отсечение префикса до первого пробела |
| У 4 городов нет данных Numbeo | `JOIN cities ⋈ city_stats`: такие города автоматически не попадают в новые категории вопросов |
| Глобальная статистика мешала мультиплееру | Таблица `players` с первичным ключом `user_id` (не меняется, в отличие от username) |
| Доступ к полям строки БД по индексам ненадёжен | `conn.row_factory = sqlite3.Row` — доступ по именам колонок |
| Бонусный вопрос выпадал слишком часто (30%) | Снижение вероятности до 10% по итогам плейтеста |
| Риск запуска бота без наполненной базы | Проверка `db_ready()` при старте с понятной подсказкой «выполни py import_data.py» |
