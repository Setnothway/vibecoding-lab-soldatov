## 1. Описание задачи  
Я решил сделать бота-мини-игру на тему географии. У бота будет большая база данных с крупными городами Земли и различными параметрами (площадь, численность населения, координаты и др.). Он будет задавать вопросы пользователю и давать варианты ответов. Например, "Какой из этих городов южнее" или "В каком из этих городов среднегодовая температура выше?" или "В каком из этих городов живёт больше всего людей?" или "Какой из этих городов располагается выше других над уровнем моря?" и т.д. Между раундами должны появляться сообщения например "Неверно😢 Южнее всего находится город Элиста" или "Верно!😜 В городе Рио-де-Жанейро живёт больше всего людей!"

### Почему выбрал именно эту задачу
- Демонстрирует работу с локальной базой данных (JSON)
- Показывает динамическую генерацию сообщений с подстановкой переменных
- Содержит элементы геймдизайна (прогрессивная сложность, streak-механика)
- Имеет практическую ценность как образовательный/развлекательный инструмент

## 2. Промпт для LLM

### Исходный промпт
```
Ты — Senior Python Developer и эксперт по созданию Telegram-ботов. Твоя задача — написать код для Telegram-бота, который представляет собой мини-игру по географии с элементами геймификации.

[БИЗНЕС-ЛОГИКА ИГРЫ]
1. Бот задает вопрос о сравнении городов по определенному параметру (население, широта, высота над уровнем моря, среднегодовая температура, площадь).
2. Бот предлагает 4 варианта ответа (1 правильный, 3 неправильных). 
3. [ГЕЙМДИЗАЙН] Сложность: Неправильные варианты должны подбираться так, чтобы их значения по сравниваемому параметру были БЛИЗКИ к правильному ответу. (Например, если сравниваем широту Парижа, то вариантами должны быть Мадрид, Рим, Берлин, а не Дубай или Осло).
4. [ГЕЙМДИЗАЙН] Рандомизация: Каждый раз вопрос и варианты должны генерироваться случайно. Если один и тот же город выпадает снова, варианты ответа (города-обманки) должны быть другими.
5. [ГЕЙМДИЗАЙН] Серии (Streak): Бот ведет подсчет серии правильных ответов. При неправильном ответе серия обнуляется. Бот запоминает максимальную серию (рекорд).
6. После ответа пользователя бот выдает динамическое сообщение:
   - Если неверно: "Неверно 😢. Правильный ответ: [Город]. [Краткий факт]. Твоя серия прервалась на [X]".
   - Если верно: "Верно! 😜. Действительно, в [Город] [факт]. Твоя текущая серия: [X]! 🔥".
7. После ответа бот автоматически предлагает сыграть еще.

[СТРУКТУРА ДАННЫХ]
1. Файл `cities.json`. Сгенерируй в нем 30 известных мировых городов. Каждый город — объект с полями:
   - "name" (название)
   - "population" (население, число)
   - "latitude" (широта, число, float)
   - "altitude" (высота над уровнем моря в метрах, число)
   - "avg_temp" (среднегодовая температура в Цельсии, число, float)
   - "area" (площадь в кв. км, число)
2. Файл `stats.json` для хранения прогресса пользователя:
   - "current_streak" (текущая серия)
   - "best_streak" (рекорд)
   - "total_games" (всего сыграно вопросов)

[ТРЕБОВАНИЯ К КОДУ]
- Используй асинхронную библиотеку `python-telegram-bot` (версии 20.x или выше, используй `Application`, а не устаревший `Updater`).
- Используй `python-dotenv` для безопасного хранения токена.
- Напиши отдельную функцию `generate_question()`, которая:
  а) Случайно выбирает параметр для сравнения.
  б) Случайно выбирает правильный город.
  в) Находит 3 других города с наиболее близкими значениями по этому параметру (используй сортировку по разнице модулей значений).
  г) Перемешивает варианты ответов.
- Код должен быть подробно прокомментирован на русском языке.
- Обязательно добавь обработку ошибок (например, если JSON не читается).

[ЧТО НУЖНО СОЗДАТЬ]
Напиши полный код для следующих файлов:
1. `bot.py` — основной код бота.
2. `cities.json` — база данных (30 городов).
3. `stats.json` — начальное состояние статистики (нули).
4. `requirements.txt` — список зависимостей.
5. `README.md` — понятная инструкция по запуску.
6. `.env.example` — пример файла с переменными окружения.
```

### Итерации и улучшения

В процессе разработки была внесена серия **ключевых правок**:

| № | Правка | Причина |
|---|--------|---------|
| 1 | **Исправлены формулировки вопросов** | Бот спрашивал «В каком из этих городов население?» — бессмысленно. Заменено на «В каком городе проживает больше всего людей?» |
| 2 | **Расширена база** | Добавлены новые вопросы и параметры: `year_founded`, `metro_stations`, `annual_tourists` |
| 3 | **Добавлена прогрессивная сложность** | Чем больше серия правильных ответов, тем ближе значения у вариантов ответа (4 уровня) |
| 4 | **Добавлено неповторение вопросов** | Хранение списка использованных комбинаций в `stats.json` |
| 5 | **Установлен размер базы в 61 города** | Слишком большая или слишком маленькая база делала игру неинтересной. Оставлены только города, знакомые среднестатистическому игроку из России |
| 6 | **Добавлен бонусный вопрос** | Специальный вопрос про Санкт-Петербург с вероятностью появления 30% при серии ≥ 2 |
| 7 | **Исправлены emoji флагов** | При копировании через Блокнот эмодзи ломались. Решено генерировать флаги программно через Unicode-последовательности |
| 8 | **Исправлена логика «больше/меньше»** | Бот не связывал формулировку вопроса с выбором ответа. Теперь сначала выбираются 4 города, потом формулировка, потом определяется правильный ответ |
| 9 | **Изменена механика сложности** | Вместо количества кандидатов введены диапазоны отклонения (процентные для населения/площади/туристов, абсолютные для остальных параметров) |
| 10 | **Добавлена таблица результатов** | После ответа показываются все 4 варианта со значениями параметра |
| 11 | **Исправлен подбор вариантов с одинаковыми значениями** | Баг: Афины и Прага обе имели 60 станций метро. Следовательно, правильных ответов два. Добавлена проверка уникальности всех 4 значений перед выдачей вопроса |

Финального промпта как такового нет, LLM просто начисто переписывала полный текст отдельных файлов (например, **bot.py**) в соответствии с указаниями на баги и предложенными нововведениями.

### Чему научился
1. **Вайб-кодинг на практике:** формулировка ТЗ на естественном языке эффективнее, чем попытки писать код вручную без опыта
2. **Итеративная разработка:** ни одна LLM не выдаёт идеальный код с первого раза — нужны тестирование и уточнения
3. **Геймдизайн:** баланс сложности, streak-механики и «пасхалки» критически важны для удержания пользователя
4. **Работа с данными:** JSON как формат хранения, важность уникальности значений, диапазоны отклонения
5. **Отладка:** умение читать traceback Python и локализовать баги (дубликаты, логика больше/меньше)
6. **Безопасность:** хранение токенов в `.env`, никогда не публиковать секреты в открытом доступе
