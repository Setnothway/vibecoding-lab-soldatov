## 1. Описание деплоя

### Какой способ выбран
Облачный хостинг **Railway** (PaaS-платформа), деплой из приватного репозитория GitHub с автоматическим CI/CD.

### Почему именно этот
| Критерий | ngrok (локально) | Railway (выбран) | Docker + VPS |
|---|---|---|---|
| Работа 24/7 без личного ПК | ❌ | ✅ | ✅ |
| Безопасность домашней сети | ❌ туннель на личный ПК | ✅ изолированный контейнер | ✅ |
| Стоимость | Бесплатно | Trial-кредит $5 | ~300 ₽/мес |
| Время настройки | 10 мин | ~30 мин | 2+ часа |
| CI/CD из коробки | ❌ | ✅ автодеплой при commit | вручную |

Дополнительный аргумент: бот использует **long polling** (`run_polling`), поэтому ему не нужен публичный HTTP-URL и webhook — сервис на Railway намеренно оставлен **Unexposed** (без открытого порта). Это уменьшает поверхность атаки: из интернета «постучаться» в контейнер невозможно.

## 2. Процесс деплоя

### Пошаговая инструкция
1. **Подготовка файлов:** созданы `.gitignore` (исключает `.env`, `*.db`, `__pycache__`), `requirements.txt` (python-telegram-bot, python-dotenv), `Procfile`, `start.sh` (импорт данных → запуск бота).
2. **GitHub:** создан приватный репозиторий `geo-quiz-bot`; 11 файлов загружены через веб-интерфейс (файлы `.env` и `geo_quiz.db` в репозиторий НЕ попадали).
3. **Railway:** New Project → Deploy from GitHub repo → сервис `worker` (Python 3.13).
4. **Секреты:** во вкладке Variables добавлена переменная окружения `TELEGRAM_BOT_TOKEN` (значение скрыто в UI и не хранится в репозитории).
5. **Команда запуска:** в Settings → Start Command указано `python import_data.py && python bot.py` (сначала ETL-импорт базы, затем бот).
6. **CI/CD:** любой commit в GitHub автоматически触发 пересборку и деплой на Railway.

### С какими проблемами столкнулись и как решили
| Проблема | Причина | Решение |
|---|---|---|
| `python: can't open file '/app/import_data.py\r'` | Скрипт `start.sh` создан в Windows Notepad с переносами строк CRLF; Linux-контейнер воспринял `\r` как часть имени файла | Команда запуска перенесена из shell-скрипта в Start Command платформы: `python import_data.py && python bot.py`; оператор `&&` дополнительно защищает от запуска бота после падения импорта |
| `ERROR — Токен не найден! Проверь файл .env` | Файл `.env` сознательно не загружается в репозиторий | Токен передан через переменную окружения Railway `TELEGRAM_BOT_TOKEN` |
| Краш `AttributeError: 'Updater' object has no attribute '_Updater__polling_cleanup_cb'` | Платформа установила Python 3.13, а закреплённая в requirements.txt библиотека python-telegram-bot 20.7 не поддерживает эту версию (поддержка добавлена в 21.6) | Версия библиотеки повышена до 21.6+; локальное и облачное окружения синхронизированы |
| Файл `.gitignore` сохранился как `.gitignore.txt` | Windows скрывает расширения и добавляет `.txt` | Переименован с включённым отображением расширений |

### Схема работы после деплоя
```
commit в GitHub ──▶ Railway: сборка образа ──▶ контейнер:
   import_data.py (cities.json + numbeo_cities.csv ──▶ geo_quiz.db)
   └──▶ bot.py ──▶ long polling ──▶ Telegram API ──▶ пользователи
```

## 5. Улучшения

### Что изменили
Исправлен массив медалей в функциях `button_handler` и `top`:
```python
medals = ["🥇", "🥈", "", "4️"]   # было: ["🥇", "", "", "4️⃣"]
```
Правка внесена через веб-редактор GitHub (commit `fix: вернул медали в таблицу и топ по фидбеку тестеров`) — Railway **автоматически** пересобрал и задеплоил новую версию примерно за 1 минуту, без участия локального компьютера. Так замкнулся полный продуктовый цикл: фидбек → правка → автодеплой → проверка.

### Как это помогло
Таблица результатов стала самодостаточной: место каждого города видно без пояснений. [скриншот shot49.png — сообщение с исправленной таблицей]
